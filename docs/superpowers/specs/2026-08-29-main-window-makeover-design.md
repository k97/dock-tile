# Main Window Makeover — Design Spec

**Date:** 2026-08-29 · **Status:** design locked, awaiting implementation plan
**Canvas (source of truth for visuals):** https://claude.ai/code/artifact/50e5d060-7281-4733-8f50-65ca058ae575
(Light and Dark pages; working files in `docs/v2/canvas/`, regenerated by `build.py`)
**Reference prototype:** `docs/v2/DockTile-Makeover-v2.html` (Claude Design export — IA reference only, not pixel truth)

## 1. Goal

Re-express Dock Tile's main window on a Klack-style surface — one-tone window, grouped white cards,
page header in the title band — with **native macOS sizing and controls** everywhere else, and make
the tile's app list a **live popover preview that is also the editor**. Fix the gaps the reference
prototype had against the real system (Dock Lock content, action-button states, missing/folder items,
zero-tile and draft states, Popover controls), add an **About** pane, and ship **light + dark**.

### Non-goals
- **Customise Tile** stays exactly as it is today (it only inherits the window chrome — see §3.2).
- No new engine behaviour: Smart Add ranking, Dock plist handling, migration, self-heal, missing-app
  detection and Dock Lock logic are untouched. This is a presentation-layer change with a few flow
  changes called out in §5.
- No website changes.

## 2. Locked decisions

| # | Decision | Choice |
|---|---|---|
| 1 | Scope | Five reference surfaces + inherited surfaces (zero tiles, draft, states) + About pane |
| 2 | Popover pane save model | **Option A — explicit Save** (⌘S) + icon-only Reset in the title band; today's draft/dirty + "Apply to your Dock tiles?" prompt unchanged |
| 3 | "In This Tile" editor | The preview **is** the editor (hover → remove badge, drag to reorder, context menu, Delete key). Adding apps keeps the **native `NSOpenPanel` with multi-select** |
| 4 | New-tile draft icon | Grey squircle with a **plus** placeholder (replaces grey `star.fill`) until the user picks an icon |

## 3. Surface and chrome

### 3.1 Window
- Fixed width **768pt** (unchanged); min height 500. `NavigationSplitView` stays (sidebar 240 ideal).
- **Chrome:** transparent unified title bar, no window title, no sidebar-toggle item, hidden toolbar
  background. The 52pt title band becomes the page header: leading title only (no icon),
  trailing actions. Sidebar column's band holds the traffic lights and the `+` (a real toolbar item,
  labelled "Add a Tile", ⌘-accessible).
- **Implementation approach (spike first):** keep SwiftUI's toolbar and place the header as toolbar
  items (`.navigation` for title, `.primaryAction` for actions) with `.toolbar(removing: .title)`,
  `.toolbarBackground(.hidden, for: .windowToolbar)`,
  `titlebarAppearsTransparent`. On macOS 26 Tahoe, toolbar items render in glass capsules — the spike
  must confirm `sharedBackgroundVisibility(.hidden)`/plain labels render flush like the canvas. Fallback:
  Klack's approach — an `NSWindow` with `fullSizeContentView`, an empty `NSToolbar` for the band height,
  and custom header views in the content (Klack's own window is an `NSToolbar` band + custom sidebar,
  verified via its accessibility tree).
- Surface tokens (light): sidebar `#E3E5E8`, window `#EEEFF1`, cards white with a ½pt 9 % hairline,
  12pt continuous card radius, 40pt form rows, 13pt labels, 11pt captions, system-blue accent. In code:
  `windowBackgroundColor` / `controlBackgroundColor` / `separatorColor` / label tiers — not literals.

### 3.2 Panes
- Every detail pane = title band + a scrolling body (20pt side padding, 18pt gaps) of grouped cards.
- **Card primitive:** Settings panes use native `Form { Section }` with `.formStyle(.grouped)`.
  Tile Detail's hero (icon column + form) and any card that hosts a preview use a shared `GroupedCard`
  container on `NSColorBackgroundView.formGroup` with the same radius/hairline, so the two cannot drift.
- **Customise Tile** keeps its current content; only its header moves into the band (back chevron +
  "Customise Tile"). Its studio canvas is out of scope for this pass.

### 3.3 Preview canvas (`PopoverPreviewCanvas`)
- One component used by Tile Detail, the Popover pane and the About hero: `StudioCanvasBackgroundView`
  (`underWindowBackground`) + the `.popover` material chrome (14pt continuous corners, hairline, shadow)
  wrapping the **real** `StackPopoverView` / `ListPopoverView`.

### 3.4 Dark mode
- Same markup, system colours. Klack-style charcoal rather than pure black: sidebar `#2C2C2E`, window
  `#323234`, cards `#3C3C3F` with a 9 % white hairline, text 92/55/35 % white tiers, sidebar selection
  11 % white, buttons `#525255`. Accent stays system blue; tile faces and app icons keep their colour;
  the canvas material darkens with the desktop. Verify the wallpaper canvas and popover material read
  correctly in both appearances.

## 4. Information architecture

Sidebar (`SidebarSelection`):
- **Tiles** — one row per tile (24pt live icon + name); a fresh draft shows the plus placeholder. Zero
  tiles → a selectable "No tiles yet" row (routes to the empty state).
- **Settings** — General · **Popover** (new top-level pane; the Appearance drill-down in General goes
  away) · Dock Lock.
- **Dock Tile** — **About** (new).
- `SettingsPane` gains `.popover` and `.about`. ⌘, still opens General.

## 5. Screens

### 5.1 Tile Detail (canvas: *Tile Detail — Grid / List / New Tile draft*)
- **Title band:** tile name (no icon) · trash icon-button (Delete Tile → existing confirmation alert) ·
  the action button. The bottom "Remove from Dock" card is removed (it deleted the tile — mislabelled).
- **Action button** = today's `resolveDockAction` seam, restyled: *Add to Dock* / *Update* prominent;
  *Remove from Dock* bordered; *Done* bordered and disabled until dirty; busy = spinner **inside** the
  button. Dock-restart consent flow unchanged.
- **Hero:** 96pt live icon + *Customise* subtle button (both open Customise), beside a card:
  *Tile Name* (inline trailing `TextField`, primary colour) · *Show Tile* · *Show in App Switcher*.
  The Layout picker moves out of the card.
- **In This Tile:** section header with caption "Hover to remove · Drag to reorder", trailing
  **Grid | List** segmented control (the tile's `layoutMode`) and **+ Add** (today's `NSOpenPanel`,
  multi-select, dedupe + beep unchanged). Below: the preview canvas showing the tile's own popover in
  its own layout, using the saved Popover settings (WYSIWYG).
- **Editing in the preview:** hover → tint + remove badge; drag to reorder; **context menu → Remove**;
  **Delete key** on the focused cell; VoiceOver "Remove" action; keyboard focus ring uses the accent.
  No bulk multi-select in the preview (the open panel keeps multi-select for adding).
- **Item states:** folders render as the real popover draws them; a missing app renders the
  `questionmark.app.dashed` placeholder, dimmed name, "Not installed" caption. Removing a missing app
  from the tile is allowed here; the launch/Scan **Remove / Keep** alert stays the only bulk-delete path.
- **Draft tile:** name "New Tile", plus placeholder icon, empty preview: "No apps yet. Use **Add** to
  choose what opens from this tile." Sidebar `+` disabled while the unedited draft is selected
  (`canCreateNewTile`, unchanged).
- **Smart Add provenance banner** stays above the hero (runtime-only, unchanged).

### 5.2 Zero tiles (canvas: *Zero tiles*)
- `ContentUnavailableView`: "Create your first tile" · "Group apps and folders behind one Dock icon.
  Start blank, or from a tile suggested from the apps you use." · one prominent **Add a Tile…** button
  that opens the dialog. Empty title band. Sidebar `+` enabled.

### 5.3 Add a Tile dialog (canvas: *Add a Tile*; no-suggestions state on *States sheet*)
- 588pt sheet. Header: "Add a Tile" + close (Esc). Body: **blank row** — plus placeholder 44pt,
  "Create a blank tile / Name it, pick an icon and add apps yourself.", prominent **Create New Tile**
  (Return default). Rule "or start from what you use". Suggestion cards (≤3): 58pt identity icon, name,
  reason chip (*By category* / *Most used this week* / *Opened together*), member icons (4 + "+N"),
  bordered *Use This Tile*. Footer: lock + "Learned on your Mac. Never leaves your device."
- **No suggestions** (Smart Add off, or nothing learned): the blank row + a quiet line "No suggestions
  yet — Dock Tile learns from the apps you open. You can turn this off in General." No cards.
- Nothing in the dialog docks a tile; *Add to Dock* stays the explicit confirm in Tile Detail.
- **Flow change:** `handleAddTapped` always presents the sheet (`SmartAddPresentation` may carry an
  empty suggestions array; the `.sheet(item:)` invariant still holds). The Smart Add toggle now governs
  whether suggestions are computed/shown, not whether the dialog appears.

### 5.4 Settings — General (canvas: *Settings — General*)
- Card: *Start tiles at login* (+ the held-for-approval row when applicable) · *Missing Apps / Check
  tiles for apps that moved or were uninstalled* → *Scan…* (results alert unchanged) · *Share anonymous
  usage data*.
- "Adding Tiles" card: *Suggest tiles from my apps / Learned on your Mac. Never leaves your device.* ·
  **Add a Tile…** action row (accent text, no chevron) → opens the dialog.
- Removed: Software Update row; the Popover/Appearance drill-down.

### 5.5 Settings — Popover (canvas: *Settings — Popover*)
- Title band: "Popover" · Reset (icon-only, tooltip "Reset to Defaults") · **Save** (prominent,
  ⌘S). Same enable/disable and "Applying…" spinner rules as today.
- Body: preview canvas (real panels, sample apps) · "Configure — Each layout is saved independently"
  + **Grid | List** panel switcher · card with the six controls (*Popover Size · Tile Size · Animation ·
  Spacing · Show Labels · Highlight on Hover*), List hides Show Labels behind "List view always shows
  labels", Reduce Motion forces Animation off with the existing caption/link · footer note.
- Everything else (draft/commit, per-layout persistence, apply prompt) unchanged.

### 5.6 Settings — Dock Lock (canvas: *Settings — Dock Lock*; conditional rows on *States sheet*)
- Restyle only. Card 1: *Lock Dock to one display* + caption. "Display" card: *Keep Dock on* popup
  (Default / displays, "(Main)" suffix) · status row (locked / moving / failed + Try Again) · footer.
  Permission row (Continue / Open System Settings…), single-display note, and the primer sheet unchanged.

### 5.7 About (canvas: *About*) — new
- Title band: "About".
- Hero: preview canvas with a Dock strip carrying three tiles and a folder (the product in context).
- Card: *Dock Tile / Version X.Y.Z* → **Check for Updates…** (Sparkle) · *Website* → docktile.rkarthik.co.
- Card: "Found a bug or have an idea?" + caption → **Send Feedback…** · **Copy Diagnostics** (the
  existing File-menu action; the menu item stays).
- "Also from Happy Machines" card: *Made by Happy Machines Company / A tiny product studio building
  nifty Mac apps that each fix one thing well.* → happymachines.company · *Spades Audio / Per-app
  volume, EQ and output control for your Mac, from the menu bar.* → **Learn More…** (spadesaudio.com).
- Footer: `NSHumanReadableCopyright`.
- Replaces `AboutWindowController` / `AboutView`; the app-menu *About Dock Tile* item selects this pane.

### 5.8 States sheet (canvas: *States sheet*)
Reference for every state the main frames can't show: action-button variants, preview cell states,
Dock Lock conditional rows, login approval row, provenance banner, no-suggestions dialog.

## 6. Invariants that must survive (from `.claude/rules`)
- `isVisibleInDock` written only by `performDockAction`; never-pinned guard; Dock restart only on real
  change; one-time Dock-restart consent; `saveOnly` never reaches `HelperBundleManager`.
- Missing-app UX non-destructive; helpers resolve status synchronously.
- Smart Add stays on-device; `.sheet(item:)`, never `isPresented` + separate array.
- Popover settings in the shared suite; "preview = the real panels"; `PopoverMetrics` is the single
  sizing seam; `isPreview` neutralises launches.
- Helpers never touch the Dock; test-host guard on launch mutators.

## 9. Accessibility
- Every hover-only affordance has a keyboard/VoiceOver equivalent (context menu Remove, Delete key,
  accessibility actions). Band `+` and action buttons are real controls with labels. Reduce Motion
  handling unchanged. Contrast checked in both appearances.

## 10. Assumptions and open items
- ⌘N *New Dock Tile* keeps creating a blank tile directly (keyboard shortcut path). Say if it should
  open the dialog instead.
- *Send Feedback…* destination (mailto vs. web form) — to be provided.
- Real logos for Happy Machines / Spades Audio replace the placeholder marks; copyright from Info.plist.
- Title weight 16pt semibold; adjust in the spike if the band wants heavier.
- App icons in the canvas are letter placeholders; the app uses `AppIconLoader`.

## 11. Testing
- Existing seams stay green: `resolveDockAction` / `dockActionIsEnabled` / `contentSignature`,
  `canCreateNewTile`, `PopoverMetrics`, `rankGroups`, `classifyInstallStatus`.
- New pure seams: the Add-flow decision (always-present + suggestions/no-suggestions state), the
  preview editor's reorder/remove reducer (plain array in/out), and the draft-icon default.
- Manual: chrome spike on macOS 26 in light/dark; Dock add/update/remove from the new band; helper
  popovers unaffected (edit mode never reaches helpers).


## Amendment — 2026-08-30 (post-build review)

- **The sidebar keeps the standard macOS header pair: collapse toggle + `+`.** Removing the toggle
  was tried and reverted; the `+` is always visible, including at zero tiles.
- **Zero tiles shows the inert, selectable "No Tiles" row.** The empty-state detail's button is the
  single add affordance; the row exists only so a user in a Settings pane can navigate back.
- **The empty tile preview's glyph is a button in the editor** — it opens the same app picker as
  "+ Add". `editing == nil` (helpers, Settings preview) leaves it an inert image.
