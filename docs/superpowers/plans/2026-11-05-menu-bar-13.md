## Batch 3 — quiet launch at login (decision 2; plan gate A–D, owner 2026-11-05)

**Owner decision (gate B):** launch maintenance (migration + self-heal) DOES run on a quiet launch, as
first promised — at most one Dock restart, on the first login after an update.

1. **Spike first (gate A), ≤ 1 h on the dev build, before any batch-3 code is kept.** On a quiet launch the
   window's `onAppear` is what hands `AppDelegate` its `configManager` and the `openWindow` action
   (`DockTileApp.swift:48`, `CaptureOpenWindow`); a suppressed window never appears, so Open Dock Tile…,
   Configure Tile…, Add a Tile…, a Finder/Spotlight reopen and the gear's deep link would all be dead.
   Candidates, in order:
   - (1) **create the window but hide it before it draws**: on a quiet launch `WindowAccessor` (first window
     creation) sets `alphaValue = 0` and `orderOut`s it; `onAppear` (handles), the `.task` (maintenance) run
     normally. Pass = a screen recording of `--quiet-launch` shows no window frame, and Open Dock Tile…
     then shows the window at full alpha (reset `alphaValue = 1` in `showConfigurationWindow`).
   - (2) `.defaultLaunchBehavior(.suppressed)` + move both hand-offs and the maintenance task out of the
     window (`AppDelegate` owns them). Only if (1) flashes.
   Record which passed, with the recording's result, in this plan before continuing.
2. `LoginTileSpawner`: pure seam `plan(visibleTiles:menuBar:mainAppRunning:) -> (helpers, launchMainApp)`;
   the main-app decision is made BEFORE the empty-tile early exit (gate C: "every tile hidden" is a
   supported menu-bar-only setup). "Main app running" excludes the spawner's own pid
   (`NSRunningApplication.current`) (gate D). Launch `Bundle.main.bundleURL` via `openApplication` with
   `createsNewApplicationInstance = true` (the spawner shares the bundle id), `activates = false`,
   `addsToRecentItems = false`, arguments `["--quiet-launch"]`; bounded wait like the helpers; on error,
   log and `exit(0)` (the icon appears the next time the user opens Dock Tile). Expected: a second process,
   the quiet main app, which outlives the spawner. Still never builds an `NSApplication` in the spawner.
   Order: the main app is launched AFTER the helper launches are acknowledged (its migration may then
   rebuild them; `runStagedRebuild`'s second quit already covers a helper relaunched mid-build).
   **Single instance (re-gate 3):** `createsNewApplicationInstance` disables Launch Services' guard, and
   macOS "Reopen windows when logging back in" can relaunch a Dock Tile whose window was open at logout
   at the same moment. So the main app holds an exclusive `flock` on `<support>/main-app.lock` for its
   whole life (the `TileBuildLock` pattern); an instance that cannot take it exits at once, before
   `configureAsMainApp`. The spawner never takes it. Pure decision + a two-open conflict test like
   `HelperSwapTests`' lock test.
3. Main app, `AppEnvironment.isQuietLaunch` — LATCHED once at process start (`static let`), = the argument
   or a fresh batch-4 relaunch flag, before the flag is cleared:
   `setActivationPolicy(.accessory)` in `applicationWillFinishLaunching` (before any Dock icon can draw,
   as helpers do); skip `AppRelocationManager.checkOnLaunch` and `TranslationInviteManager.checkOnLaunch`
   (next normal launch); the spike's hide mechanism.
4. "Start tiles at login" caption: extend it to mention the menu bar icon only if the l10n round trip
   allows a clean wording — otherwise leave it (gate G).
5. Tests: `LoginSpawnPlanTests` — zero visible tiles + menu bar on → launches main app; menu bar off → no
   main app; main app already running (other pid) → no second; own pid not counted.

Verify: quit the dev app; run the dev binary with `--login-spawn-tiles` (the agent's own command): helpers
warm, a NEW quiet main app runs (pid ≠ spawner's), icon present, no window frame (screen recording), no
Dock icon, no alerts, `[migration]` lines in the log; Open Dock Tile…, Configure Tile…, `open -a`, a gear
deep link all work; a second `--quiet-launch` while one runs exits on the lock. Then real logout/login
(owner, when convenient), once with the window CLOSED and once with it OPEN ("Reopen windows" on):
exactly one main-app process afterwards. Note: an unreadable config still shows its quit alert at a quiet
login (the window `.task` runs) — correct, and the only alert a quiet launch can show.

## Batch 4 — install updates while idle (owner, 2026-11-05)

Sparkle installs a silent update when the app QUITS; with the menu bar icon on, Dock Tile rarely quits.
`SPUUpdaterDelegate.updater(_:willInstallUpdateOnQuit:immediateInstallationBlock:)` (Sparkle 2.9 header,
checked): return YES to take control, then call the handler to install + relaunch with no UI; Sparkle
still installs on termination either way.

**Owner, 2026-11-05:** scope = whenever Dock Tile stays resident (`staysResident(dockLock:menuBar:)`, so
Dock Lock users too); ship only after a real end-to-end install (below).

1. `UpdaterDelegate` (`UpdateController.swift`): when `staysResident`, keep the handler and return YES;
   otherwise return NO (today's behaviour, unchanged).
2. Install when the pure seam `IdleInstall.shouldInstall(windowVisible:secondsSinceInput:dockBusy:)` holds —
   the configuration window not VISIBLE (`isVisible`: after a quiet launch the hidden window still exists
   in `NSApp.windows`), ≥ 600 s with no input, and no Dock operation in flight
   (`HelperBundleManager.isDockOperationInFlight` for any tile). Input age =
   `CGEventSource.secondsSinceLastEventType(.combinedSessionState, eventType: CGEventType(rawValue: ~0)!)`
   (`kCGAnyInputEventType`; NOT `.null`, which is event 0). Checked on a 60 s timer that runs ONLY while a
   handler is pending, and on window close. Dev check: log the reading; it resets on a key press and climbs
   while idle; no TCC prompt appears (if one does: stop and ask the owner).
3. Before calling the handler, write `relaunchQuietlyAt = now`; at launch, `isQuietLaunch` honours it only if
   it is under 120 s old, then clears it (a failed install can't make the next normal launch silent). The
   relaunched app's launch maintenance then rebuilds tiles (the one Dock restart) while the user is idle.
4. Log non-verbose (`update`: "installing while idle after N s"); reuse `update_installing`.
5. Tests: `IdleInstallTests` (visible → no; 599 s → no; 600 s → yes; Dock busy → no) and the relaunch-flag
   age rule (119 s → quiet, 121 s → normal, absent → normal).

**Ship bar (owner): a real end-to-end install before merge.** Scratch build only, never committed: a
throwaway `generate_keys` key pair (its `SUPublicEDKey` in the scratch Info.plist, never the real one), a
local appcast served from the scratch folder offering a higher build signed with the throwaway key, the idle
threshold shortened via a dev-only `defaults` override read at the call site (deleted afterwards, the
driving-the-dev-build experiment pattern). Pass = with the window closed and no input, the scratch app
installs, relaunches quietly (no window, icon present), and its log shows the new build number. Fail or
not feasible → batch 4 does not merge.

**Biggest risk (re-gate 2):** returning YES stalls Sparkle's update cycle until the handler runs or the app
quits; a trigger that never fires would stop updates for resident users with no remote fix. The
end-to-end bar above is the guard.

## Risks

- `.accessory` ⇄ `.regular` switching has AppKit focus quirks (a window opened while `.accessory` may not
  come to front) — the hands-on list covers open/close/reopen/⌘Tab.
- `DockTileApp.init()` now creates `ConfigurationManager` — same moment as before in practice (launch);
  under the test host it is created exactly as before (`isRunningTests` guards inside are unchanged).
- A quiet login launch runs migration/self-heal (owner's choice): the first login after an update may
  restart the Dock once.
- Install-while-idle quits and relaunches the main app on its own; the idle gate (window closed + 10 min no
  input) is what keeps the Dock restart away from active use. If `secondsSinceLastEventType` needs a TCC
  grant, stop and ask the owner (no new permission prompt is acceptable without their say).
- Menu rebuild per open renders N tile icons via `ImageRenderer` — measure once with 10+ tiles; if it
  stalls the menu, cache per `iconSignature`.
